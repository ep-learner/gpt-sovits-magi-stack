# 架构说明

> 本文回答：整套方案用了哪些软件，每个软件负责什么，数据如何流转。

## 一、总体架构

整条链路由两段拼成，中间靠一个本地 HTTP API 解耦：

```
┌──────────────────────────────────────────────────────────────────┐
│                         训练阶段（一次性）                         │
│                                                                  │
│  目标人声素材(1~5min)                                             │
│       │                                                          │
│       ▼                                                          │
│  ┌─────────────────────────────────────────────┐                 │
│  │  GPT-SoVITS（WebUI / 无头驱动 train_v2pro.py）│                │
│  │  ┌──────────┐ ┌────────┐ ┌─────┐ ┌────────┐ │                 │
│  │  │ UVR5 去噪 │→│ 音频切片│→│ ASR │→│ 人工校对│ │                 │
│  │  └──────────┘ └────────┘ └─────┘ └────────┘ │                 │
│  │                       │ 生成 .list 训练集      │                 │
│  │                       ▼                       │                 │
│  │  ┌─────────────────────────────────────────┐ │                 │
│  │  │  v2Pro 微调训练（参数默认，关 DPO）       │ │                 │
│  │  └─────────────────────────────────────────┘ │                 │
│  └───────────────────────┬─────────────────────┘                 │
│                          ▼ 产出                                   │
│              微调模型 ckpt（音色 + 会说话的能力）                   │
└──────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌──────────────────────────────────────────────────────────────────┐
│                      运行阶段（日常听书，常驻）                    │
│                                                                  │
│  ┌──────────────┐   POST /tts    ┌──────────────────────────┐    │
│  │ MAGI 阅读器   │ ─────────────▶ │  GPT-SoVITS API 服务      │    │
│  │ (Electron)   │                │  api_v2.py (uvicorn:9880) │    │
│  │              │ ◀───────────── │  加载: 微调模型 + 参考音频 │    │
│  │ · EPUB/TXT   │   返回 wav     │  + 参考文本 → 合成语音     │    │
│  │ · 逐句高亮   │                └──────────────────────────┘    │
│  │ · 播放控制    │                                                │
│  └──────────────┘                                                │
└──────────────────────────────────────────────────────────────────┘
```

### GPT-SoVITS 整合包内部结构（关键部分）

```
GPT-SoVITS-v2pro-20250604\    ← 运行时根目录（所有命令在此目录下执行）
├── runtime\python.exe        ← 内置 Python 3.9 嵌入版，所有命令都用它，不用系统 python
├── go-webui.bat              ← 启动训练 WebUI（端口 9871~9874）
├── api_v2.py                 ← 启动推理 API 服务（端口 9880）★ 阅读器连这个
├── webui.py                  ← WebUI 入口
├── GPT_SoVITS\
│   ├── pretrained_models\    ← v2Pro 基础模型（下载自带）
│   │   └── v2Pro\            ← s2Gv2Pro.pth / s2Dv2Pro.pth 等
│   └── configs\tts_infer.yaml ← 推理配置（custom 段指向训练产出的权重）
├── output\slicer_opt\<实验名>\ ← 切片数据集（兼作参考音频来源）
├── logs\<实验名>\            ← 1abc 预处理产出（HuBERT / sv / 语义 token）
├── SoVITS_weights_v2Pro\     ← 训练产出：<实验名>_e8_s184.pth
├── GPT_weights_v2Pro\        ← 训练产出：<实验名>-e15.ckpt
└── tools\
    ├── uvr5\                 ← 人声/伴奏分离（素材有噪声时用）
    └── asr\                  ← FunASR 中文转写 + Faster-Whisper
```

## 三、为什么这样拆分

1. **训练与推理分离**：训练在 WebUI 里人工介入（切片、校对），推理走无人值守的 API。阅读器只需要跟 API 对话，不必感知模型细节。
2. **WebUI ≠ API**（PRD 强调的最大坑）：
   - `go-webui.bat` → WebUI，端口 9871~9874，给人点鼠标用，**没有 `/tts` 接口**。
   - `api_v2.py` → API 服务，端口 **9880**，给程序调用，**有 `/tts` 接口**。
   - MAGI 必须连 9880，连错就报 `Failed to fetch`。
3. **音色由「参考音频」决定，模型只提供「会说话的能力」**：换模型不换参考音频会得到杂交音；反之参考音频要 3~6 秒、干净、语气平稳，且提示文本必须与音频逐字一致。

## 四、运行时数据流（听书时）

```
用户在 MAGI 点「朗读当前句」
  │
  ▼
MAGI 读取该句文本（如 "天色渐晚，江面上起了薄雾。"）
  │  POST http://127.0.0.1:9880/tts
  │  body: { text, text_lang:"zh", ref_audio_path, prompt_text, prompt_lang }
  ▼
api_v2.py 收到请求
  │  1. 加载微调模型（首次请求加载，之后常驻显存）
  │  2. 读取参考音频 + 参考文本（锁定音色）
  │  3. 推理生成该句的 wav
  ▼
返回 wav 音频流
  │
  ▼
MAGI 播放，同时高亮当前句；播完自动请求下一句
```

## 五、资源需求（本机实测）

| 资源 | 需求 | 本机现状 |
|---|---|---|
| GPU | NVIDIA ≥6GB（8GB 舒适），训练 v2Pro | RTX 4060 Ti **8GB** ✅ |
| 磁盘 | 整合包解压后约 15~20GB + 模型 + 素材 | D 盘 380GB 空闲 ✅ |
| 系统 | Windows 10/11 | Windows ✅ |
| 网络 | 仅下载阶段需要（约 8GB 整合包 + 144MB MAGI） | 已具备 |
| 显存占用 | 听书时仅 API 常驻约 2~4GB；训练时需 6GB+ | 听书前需关闭占用显存的程序 |

## 六、与本仓库的关系

本仓库**只交付文档 + 启动脚本 + 配置模板**，不包含 30GB 的整合包和模型大文件（它们部署在仓库同级的 `aiVoiceDep\` 下，由 `config\stack.yaml` 的 `dep_root` 指向）。仓库的作用是：

- 记录方案、架构、使用方法，保证可复现；
- 提供一键启动脚本，把「起服务」从一行易出错的命令固化成双击即用；
- 作为交付物的入口（README 指向本机部署位置）。
