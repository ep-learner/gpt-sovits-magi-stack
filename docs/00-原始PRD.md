# 用 GPT-SoVITS 克隆音色 + MAGI 听小说：从造模型到整本朗读

> 本文为需求原始 PRD，原样存档，作为本仓库方案设计的输入来源。
> 来源：用户提供的背景文档。

前段时间想把自己喜欢的声音用来读小说，折腾了几天跑通了整条链路，写下来给有同样需求的朋友。

先说结论：**能跑通，成本不高，8G 显存的笔记本就够。** 造一个音色模型大约 1 小时（训练本身只要几分钟），之后每次听书就是双击一个脚本 + 打开阅读器。

现成的商业软件基本没有能干这个的，所以只能自己把两段拼起来：

```
GPT-SoVITS（造音色 + 出音频）  →  MAGI（阅读器，负责显示和播放）
```

## 一、需要准备什么

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 |
| 显卡 | NVIDIA，**6 GB 显存起步，8 GB 舒服**（我用 4060 Laptop 8G） |
| 磁盘 | 预留 **30 GB 以上** |
| 素材 | 目标音色的干净人声，**1~5 分钟**就够 |
| 软件 | GPT-SoVITS 整合包、MAGI 阅读器（都免费开源） |

## 二、第一步：造音色模型

这一步不用我重写教程，官方手册做得很完整，**照这篇走就行**：

> **GPT-SoVITS 指南（白菜工厂1145号员工）**
> https://www.yuque.com/baicaigongchang1145haoyuangong/ib3g1e

配套视频（13 分钟，讲整合包全流程）：https://www.bilibili.com/video/BV14xS8BDE1w/

下面只补充几个**视频里一句话带过、但实际最容易翻车**的点：

### 1. 开工前关掉三样东西

- **全局代理 / 梯子** —— 不关会各种莫名其妙的报错
- **浏览器的网页翻译** —— 会把 WebUI 界面翻译成奇怪的中文，按钮全找不到
- **杀毒软件** —— 会误杀、拖慢解压和训练

### 2. 选对整合包

**只有 RTX 50 系**才下 `nvidia50x0` 那个包，**其他所有 N 卡（含 40/30/20 系）都下常规包**。选错能启动，但没必要将就。

### 3. 素材处理顺序

```
有背景音乐/噪声 → UVR5 人声分离 → 语音切分
素材本来就干净 → 直接语音切分
```

切完**一定要按"时长"排序，把超过 15 秒的删掉**。这一步偷懒，后面训练必出怪声。

如果切出来几乎全是超长片段，说明素材断句间隔太短，把切分参数里的 `300` 改成 `100` 或 `200` 重切，**其他参数别碰**。

### 4. ASR 之后必须校对

视频说校对"可以跳过"，但**强烈建议至少抽查前 20 条**。

ASR 听错一个字，这个错字就原样进了训练集，直接反映成咬字不准。我自己的素材里就有数字被听成"QQ号"的情况。

### 5. 版本选 v2Pro，参数全默认

- 版本：**v2Pro** 或 v2ProPlus，两者差距不大
- **训练参数一个都别改**，软件已经按你的显存自动调好了
- **DPO 训练不要开**，实验性功能，反馈普遍是弊大于利

### 6. 8 GB 显存的限制

| 版本 | 8G 能否训练 |
|---|---|
| v2Pro / v2ProPlus | ✅ 可以 |
| v3 | ⚠️ 只能 LoRA |
| v4 | ❌ 全量要 12G |

所以 8G 卡老老实实 v2Pro。

## 三、第二步：起 API 服务（这里最容易卡住）

模型训完，WebUI 里能试听，但**阅读器连不上 WebUI**。这是最多人卡住的地方，我当初也绕了一圈。

### 关键认知：WebUI 和 API 是两个东西

| | WebUI | API |
|---|---|---|
| 启动方式 | `go-webui.bat` | `api_v2.py` |
| 端口 | 9871~9874 | **9880** |
| 用途 | 人点鼠标调参 | **程序调用** |
| 有 `/tts` 接口吗 | ❌ 没有 | ✅ 有 |

**阅读器要连的是 API，不是 WebUI。** 我第一次把地址填成 WebUI 端口，报 `Failed to fetch`，查了半天。

### 启动命令

在整合包根目录开一个命令行：

```bat
runtime\python.exe api_v2.py -a 127.0.0.1 -p 9880 -c GPT_SoVITS/configs/tts_infer.yaml
```

看到这行就是成功了，**窗口别关**：

```
Uvicorn running on http://127.0.0.1:9880
```

> 三个参数其实都是默认值，只写 `api_v2.py` 也能跑。写全是为了以后不迷糊。

做个 `start.bat` 双击启动更省事，注意加个端口占用检查，不然容易起出两个实例打架。

## 四、第三步：MAGI 配置

MAGI 是个本地阅读器（Electron 做的），支持 EPUB / TXT，带逐句高亮朗读。

> 项目：https://github.com/noemoe5/MAGI
> 下载：https://github.com/noemoe5/MAGI/releases

### 设置里填 4 个字段

| 字段 | 填什么 |
|---|---|
| **base_url** | `http://127.0.0.1:9880` |
| **参考音频** | 参考音频的完整路径，**不要带引号** |
| **提示文本** | 必须和参考音频**一字不差** |
| **语言** | `zh` |

### 三个坑

**① 参考音频路径不能带引号。** 从资源管理器「复制为路径」粘进去会带引号，服务端直接报 400。

**② 提示文本要逐字一致，标点也算。** ASR 出来的是半角 `,` 和 `.`，如果你改成全角 `，` `。`，相似度会掉。

**③ 参考音频和模型必须配套。** 音色是参考音频决定的，模型只提供"会说话的能力"。换了模型不换参考音频，会得到很怪的杂交音。

### 参考音频怎么挑

- 时长 **3~6 秒**（超过 10 秒直接报错）
- 单人、无背景音乐、无混响
- **语气平稳** —— 别挑喊叫、耳语、哭腔的段落，模型会把这股劲儿带到整本书里

## 五、实测性能（4060 Laptop 8G）

| 文本长度 | 音频时长 | 生成耗时 | 倍速 |
|---|---|---|---|
| 10 字 | 2.5 s | 1.5 s | 1.7× |
| 25 字 | 6.7 s | 2.9 s | 2.3× |
| 65 字 | 15.2 s | 6.3 s | 2.4× |

**整体约实时的 2.4 倍速**，跟得上正常朗读节奏。短句因为固定开销占比高，会显得慢些。

听感上会有句间停顿——因为阅读器是逐句请求合成的。把语速设成 1.1~1.2 能明显缓解。

## 六、踩坑清单

| 现象 | 原因 | 处理 |
|---|---|---|
| **`Failed to fetch`** | 服务没起，或地址填错 | 确认终端里有 `Uvicorn running`；核对端口是 **9880** |
| `TTS 请求失败 (400)` | 参考音频路径不存在 / 带引号 / 超 10 秒 / 语种代码错 | 逐个排查 |
| 声音不像 | 参考音频不对，或参考文本和音频对不上 | 换 5 秒干净片段，逐字核对 |
| 越听越卡 | WebUI 的推理页也开着，两个模型抢显存 | 日常听书只开 API，别开 WebUI |
| **端口报 `Cannot find empty port`** | Windows 的 Hyper-V/WSL 预留了一段端口，落在里面谁绑不上，`netstat` 也查不出来 | 改 `config.py` 端口（我换到了 15001~15004） |
| 合成胡言乱语 | 单次文本太长 | 一次别超 50 字，按句切 |

## 七、几点说明

**关于效果**：音色相似度确实可以做到"一听就知道是谁"的水平，但**说话的习惯学不到**——口癖、气口、笑腔这些是第二层信息，模型给不了。读长篇小说会逐渐趋向一种"播音腔"。这是目前所有少样本方案的共同局限。

**关于素材类型**：用什么类型的录音训练，就会得到什么气质的模型。用朗读类素材（有声书、播客、访谈）训出来的模型天生就会"念书"；用情绪化、贴麦的素材训，读小说会很违和。**选素材比调参数重要十倍。**

**关于合规**：
- 克隆可识别的真人声音（尤其是商业配音、声优、公众人物）**需要本人授权**。《民法典》第 1023 条把声音权益参照肖像权保护。自己听风险较低，公开发布或商用是明确的法律风险。
- 朗读受版权保护的作品并公开传播，另需著作权授权。
- 按 GPT-SoVITS 的使用规约，**公开发布基于它制作的作品时需要署名 GPT-SoVITS 工具**，否则违反开源协议。
